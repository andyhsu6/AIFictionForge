# 关系类型扩展与多类型角色关系设计

## 背景

当前 `relationship_types` 是全局固定 21 种关系类型，`character_relationships` 以同一对角色去重，导致：

- 小说导入后的关系经常落在 21 种之外，覆盖不足。
- 同一对角色只能表达一种关系，无法表达师生、姐弟、情侣同时成立的情况。
- 角色/关系生成不读原文，关系是模型现编的，不是从原文提取的。

目标：

- 导入小说时从原文抽取人物关系，关系类型优先来自原文。
- 系统没有的关系类型自动补录为项目级类型，也支持手工新增。
- 一条角色关系可挂多个关系类型；同一对角色允许多条关系记录。

## 数据模型

### relationship_types

- 增加 `project_id`：`NULL` 表示系统预置类型，非空表示项目级类型。
- 增加 `source`：`system` / `import` / `manual` / `analysis`。
- 增加 `is_system`：用于快速区分系统预置类型，等价于 `project_id IS NULL`。
- `name` 在系统级和项目级分别唯一；项目级唯一约束为 `(project_id, name)`。
- 系统预置类型只读，项目级类型可增删改。

### character_relationship_type_links

- 新建关联表，字段：`relationship_id`、`relationship_type_id`、`created_at`。
- `(relationship_id, relationship_type_id)` 唯一。
- 外键级联删除。
- 这是关系与类型之间的唯一权威数据源。

### character_relationships

- 移除冗余列 `relationship_type_id`。
- `relationship_name` 保留为可选自定义标签，不再作为展示名权威字段。
- 不再对 `(character_from_id, character_to_id)` 做唯一约束。
- 同一对角色允许多条关系记录，每条可挂多个类型。

### characters

- 增加 `source`：`system` / `manual` / `ai` / `imported`。
- 原文抽取自动补的角色标记为 `imported`。

## 关系类型管理 API

- `GET /api/relationships/types?project_id=...`：返回系统预置类型 + 项目级类型。
- `POST /api/relationships/types`：创建项目级类型；同名已存在则复用，不新建。
- `PUT /api/relationships/types/{id}`：修改项目级类型；系统类型禁止修改。
- `DELETE /api/relationships/types/{id}`：删除项目级类型；若仍被关系引用则禁止删除。

创建/更新关系接口：

- 接受 `relationship_type_ids` 数组。
- 也接受 `relationship_type_names` 数组；提交不存在的名称时自动补录为项目级类型。

## 类型泛化规则

关系类型必须是可复用泛化标签，例如：

- 接受：`宗门弟子`、`宗门记名弟子`、`同门`、`主仆`、`契约`。
- 拒绝：`玄天宗记名弟子`、`九尾狐契约`、`林家三少爷`。

提示词要求 AI 输出泛化标签，把具体情节写进描述。后端归一化兜底：

- 去除首尾空白。
- 长度限制：最多 50 字。
- 与已有类型同名时复用已有类型，不新建。
- 含明显专名特征（如地名、门派名、姓氏+称谓）的长标签降级到关系描述。
- 单次导入新增类型设上限，避免类型池膨胀。

## 原文关系抽取

新增导入步骤 `relationship_extraction`：

- 在角色/组织生成之后执行。
- 按导入配置（整本 / 末 x 章）分批采样章节正文。
- 每批最多 5 章，单章截断到合理长度。
- 调用新增 `RELATIONSHIP_EXTRACTION` 提示词。

抽取输出结构化关系：

- 角色 A
- 角色 B
- 关系类型数组
- 亲密度
- 状态
- 描述
- 出处章节
- 原文证据

落库规则：

- 类型必须泛化，具体情节写入描述。
- 未命中类型自动补录为项目级类型。
- 同一对角色允许多条关系记录；只有同对 + 相同规范化类型集合 + 同来源批次才合并。
- 已存在同对关系时，把抽取类型并入现有关系的类型集合并追加描述，不覆盖原描述。
- 原文中角色生成遗漏的重要人物按频次自动补为轻量角色（单次上限 30 个）。
- 抽取失败不阻断导入，记入失败步骤，可重试。

## 章节分析写入关系

- 章节分析更新已有同对关系时，不覆盖原关系。
- 变化描述追加到原描述，并新建一条 `source=analysis` 的关系记录。
- `relationship_name` 不被章节分析覆盖。

## 前端

### 关系管理页

- 类型 Tab：增加新增、编辑、删除入口和来源标签。
- 添加/编辑关系：多选类型（系统预置 + 项目级 + 可自定义输入）。
- 关系列表：按角色对分组，默认显示合并摘要，可展开多行。
- 关系列展示多个类型 Tag。

### 关系图谱

- 一对角色只画一条线，线上标全部类型。
- 标签较长时不在线上堆叠，点击边查看完整详情。
- 颜色/分类按主类型判定。

### 角色页

- 关系摘要保持文本兼容，自动包含多类型。

## 迁移与兼容

- 编写 SQLite 和 Postgres 双迁移。
- 迁移顺序：
  1. 建关联表。
  2. 回填现有 `relationship_type_id` 到关联表。
  3. 移除 `character_relationships.relationship_type_id` 列。
  4. 为 `relationship_types` 增加 `project_id`、`source`、`is_system`。
  5. 将现有 21 种预置类型标记为系统类型。
- 现有关系数据全部保留。
- 项目导出/导入增加 `relationship_type_names` 数组，导入时重建项目级类型。
