## Error-mapping helper signatures (unit-testable, no React)
mapErrorPayload(payload: { detail?, code?, params?, status? }): string
mapSSEError({ error?, error_code?, error_params? }): string
mapSSEProgressMessage({ message?, message_code?, message_params? }): string
mapTaskStatusMessage({ status_message?, status_code?, status_params? }): string
isUnauthenticatedError(code?, status?): boolean
normalizeErrorCode(code: string): string          // 'errors.validation.string' → 'validation.errors.validation.string'
setErrorTranslator(t)                             // DI seam; src/i18n/index.ts injects the app instance

Resolution order in mapErrorPayload:
1. code='dynamic_detail' → raw detail (runtime text wins)
2. code='http_error' → errors:http_error template '{{detail}}' (raw preserved)
3. known code → errors:<normalized key>, params interpolated
4. unknown code → raw detail (NEVER dropped — hard backward-compat rule)
5. no code/detail → per-status fallback key (http.badRequest…http.errorWithStatus) → errors:unknown

## Deviations
- errors.json key shape uses nesting groups (auth/unauthorized → "auth.unauthorized") which is what
  the i18next-cli types generator flattens into typed keys; http_error/dynamic_detail/unknown stay
  flat leaf keys (contain underscores, valid as literal keys).
- errorMapper uses an injection seam (setErrorTranslator) instead of importing src/i18n directly,
  so the standalone .mjs unit test can run without DOM/browser init order issues (same pattern as
  todo 1's normalize.test.mjs).
- SSE POST non-2xx path now parses the JSON envelope (was: bare `HTTP error! status: N`).
- api.ts toast call kept on `antdMessage.error` (the App-context bridge introduced by the
  concurrent todo-2 antd static-API migration, commit 206198e) — no other business files touched.
- build emits assets to ../backend/static (pre-existing vite outDir; build output gitignored,
  no backend source touched).
