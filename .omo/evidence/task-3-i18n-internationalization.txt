PRIORITY-CONTRACT IMPLEMENTATION MAP:
  1) Not logged in (Login page pre-auth / pre-AuthCallback):
     detector order [localStorage, navigator, htmlTag] guides language
     (todo 1, untouched). No sync call happens before authentication:
     Login.tsx only calls syncLanguageWithServer() inside
     handleLoginSuccess (after cookie session exists); AuthCallback only
     after getCurrentUser() resolves; ProtectedRoute only in its
     post-getCurrentUser success branch.
  2) After authentication server = single source of truth:
     syncLanguageWithServer() on every auth success + every protected-route
     mount: server preferences.language present -> changeLanguage(server)
     over local residue. Seed case: server has no language yet -> current
     local language is mirrored UP (first-write wins, then server rules).
  3) User actively switches (Settings page):
     handleLanguageChange writes BOTH directions:
     (a) i18n.changeLanguage -> detector caches localStorage 'lng'
     (b) PUT /settings/preferences -> preferences.language
  4) Logout keeps localStorage:
     UserMenu.handleLogout untouched (authApi.logout + redirect only);
     nothing in this task clears 'lng'. Next login re-syncs from that
     account's server preference (rule 2 overrides residue).
  5) Same-browser multi-account no pollution:
     localStorage is transient residue; each login/protected-mount runs
     syncLanguageWithServer which reads THAT account's settings row
     (require_login -> per-user_id Settings), so account A's preference
     never survives into account B's session beyond a refresh cycle.
     Backend merge-write keeps other preference keys per-account.
